# OffersBucket architecture

## Product direction

OffersBucket keeps offers useful without requiring an account or network connection. Device storage is the source of truth for the MVP. Account sign-in and optional sync become a second layer.

## Flutter choice

Flutter is the right fit for this product: one UI codebase for Android and iOS, simple responsive screens, and a clean seam for platform-specific integrations.

## Local-first flow

1. `OfferRepository` owns active/archive/search/sort/favorite behavior.
2. `LocalOfferStore` serializes offers into device storage.
3. App starts from local offers and archives expired offers during startup.
4. A future sync adapter can push/pull only after local changes are saved.

The current storage format is versioned with `offersbucket.offers.v1`. Do not write Supabase calls directly inside widgets; add a store/sync adapter instead.

## Supabase recommendation

Use Supabase for the account and optional cloud backup layer, not as the only offer database. It gives Flutter a managed Postgres database, email/password auth, row-level security, and a straightforward REST/realtime client. Keep the app usable when signed out or offline.

Suggested sync rules:

- Every offer has a stable device-generated `id`.
- Upload only offers the user chooses to sync.
- Store `updated_at` and `deleted_at` for conflict handling.
- Resolve simple conflicts with last-write-wins initially; preserve local data if sync fails.
- Keep provider tokens out of offer rows. Store only provider connection metadata in a protected table.

## Notification capture constraints

- Android can support a user-enabled notification listener integration, subject to Android permissions, OEM behavior, and Play policy review.
- iOS does not provide a general API for reading notifications generated by other apps. On iOS, support email import, share-sheet capture, manual entry, and app-owned reminders instead.
- Email ingestion should be opt-in, scoped to selected messages, and processed with least-privilege provider access.

## Android capture implementation

- `OfferNotificationListenerService` receives Android notification callbacks.
- `NotificationCaptureStore` is native local storage so capture continues while
  the Flutter engine is closed.
- Capture is denied unless the user enables capture and the source package is in
  the selected allowlist. Changing allowlist removes unsaved captures from
  removed packages.
- `InstalledApps` exposes launchable apps and mail handlers without requesting
  unrestricted package visibility. Newly installed apps are never allowed
  automatically.
- Flutter reads native state through the
  `offersbucket/notification_capture` method channel and receives refresh
  signals through its event channel.
- Email support means notification previews from selected email apps, not
  inbox synchronization. Full inbox access remains a separate provider OAuth
  feature.

## Web deal search

- Explore uses Actually Useful Deals' public read-only `/wp-json/aud/v1/deals`
  endpoint, which does not require an API key or account.
- The app fetches active deals, filters them locally by title, merchant,
  category, discount, and use case, then opens the public merchant/deal URL.
- Web results are never inserted into local coupons automatically. The user
  must inspect the external deal and add a coupon manually if needed.

## Expiry reminders

- `ExpiryReminderService` uses local device notifications; no server or account
  is required.
- Active coupons receive one reminder scheduled 24 hours before expiry. Coupons
  expiring in less than 24 hours receive a near-term reminder instead.
- Schedules are rebuilt after coupon saves/imports and when the setting changes.
- Android notification permission is requested before scheduling. Disabling the
  setting cancels pending reminder notifications.

## Remaining implementation slices

1. Add onboarding explaining Android notification access and iOS alternatives.
2. Add sync status and a manual “Sync now” action.
3. Add notification preferences for expiring soon, favorites, and high-value deals.
